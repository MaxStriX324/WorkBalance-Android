# Постоянный установочный APK

## Зачем нужен собственный ключ

Android устанавливает новую версию поверх старой только при совпадении идентификатора приложения и цифровой подписи. Один и тот же файл ключа необходимо использовать для всех следующих версий. Если ключ потерян, обновить установленное приложение невозможно без удаления старой версии и её локальных данных.

## Создание ключа в Android Studio

1. Открыть `Build → Generate Signed App Bundle or APK`.
2. Выбрать `APK`, затем модуль `app`.
3. Нажать `Create new`.
4. Сохранить ключ вне папки проекта, например `D:\Android\keys\workbalance-release.jks`.
5. Задать надёжный пароль хранилища, alias `workbalance`, пароль ключа и срок действия не менее 25 лет.
6. Сохранить JKS и оба пароля минимум в двух защищённых местах.
7. Выбрать вариант `release` и обе версии подписи `V1` и `V2`, затем выполнить сборку.

Готовый файл обычно создаётся в `app\release\app-release.apk` или `app\build\outputs\apk\release\app-release.apk`.

## Установка обновлений

- не менять `applicationId = "ru.maxstrix.workbalance"`;
- для каждой публикации увеличивать `versionCode`;
- всегда выбирать тот же `workbalance-release.jks` и alias;
- открыть новый APK на телефоне и подтвердить «Обновить»;
- не удалять приложение и не нажимать «Очистить данные».

## Переход с текущей debug-версии

Debug- и release-APK имеют разные подписи. Release-версия не установится поверх уже установленной debug-версии. Пока данных мало, безопаснее вручную переписать отметки, удалить debug-версию и установить постоянную release-версию. После этого все следующие release-обновления будут сохранять данные.

Для временного тестирования коллега может установить `app-debug.apk`. Такие debug-обновления будут устанавливаться поверх него, пока сборка выполняется на том же компьютере с тем же файлом `%USERPROFILE%\.android\debug.keystore`.
